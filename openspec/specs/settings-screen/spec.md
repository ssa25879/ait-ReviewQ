# settings-screen Specification

## Purpose
설정 화면에 어디서 들어가는지, 저장 위치를 어떻게 알리는지, 전체 삭제와 복습 알림 재요청을 어떤 조건과 확인 절차로 제공하는지 정의한다.

## Requirements

### Requirement: 설정 진입
홈 화면은 설정 화면으로 가는 동작을 통계 진입 아래에 제공해야 한다(SHALL). 설정 화면에서 뒤로가기를 하면 홈으로 돌아가야 한다. 설정 화면 주소로 바로 열거나 새로고침해도 설정 화면이 열리고, 뒤로가기를 하면 홈으로 간다.

#### Scenario: 홈에서 설정 열기
- **WHEN** 홈에서 설정 동작을 누른 뒤 뒤로가기를 누른다
- **THEN** 설정 화면이 열렸다가 홈으로 돌아온다

#### Scenario: 설정 주소로 바로 열기
- **WHEN** 설정 화면 주소로 앱을 열고 뒤로가기를 누른다
- **THEN** 설정 화면이 보이고, 뒤로가기 후 홈이 보인다

### Requirement: 저장 위치 고지
설정 화면은 맨 위에 학습 데이터가 이 기기에만 저장되며 토스 앱을 지우거나 기기를 바꾸면 사라진다는 안내와, 백업 내보내기를 권하는 안내를 항상 보여 주어야 한다(SHALL). 카드가 없을 때도 보인다.

#### Scenario: 고지 표시
- **WHEN** 카드가 0장인 상태에서 설정 화면을 연다
- **THEN** 기기에만 저장된다는 안내와 내보내기 권장 안내가 보인다

### Requirement: 전체 삭제 2단계 확인
설정 화면은 "모든 데이터 삭제" 동작을 위험 스타일로 제공해야 한다(SHALL). 누르면 지워지는 대상과 되돌릴 수 없다는 점을 알리는 첫 번째 확인을 보여 주고, 계속하면 한 번 더 최종 확인을 받아야 한다. 어느 단계에서든 취소하면 아무것도 지우지 않는다.

#### Scenario: 첫 확인에서 취소
- **WHEN** "모든 데이터 삭제"를 누르고 첫 번째 확인에서 취소한다
- **THEN** 저장 데이터가 그대로이고 설정 화면에 머문다

#### Scenario: 최종 확인에서 취소
- **WHEN** 첫 번째 확인에서 계속한 뒤 최종 확인에서 취소한다
- **THEN** 저장 데이터가 그대로이다

### Requirement: 전체 삭제 실행
최종 확인을 받으면 시스템은 이 앱의 저장 데이터(과목·덱·카드·판정 기록·Meta·자동 백업·격리 원본)를 모두 지우고, 첫 실행과 같은 빈 상태로 홈을 열어야 한다(SHALL). 삭제 전에 저장 대기 중이던 변경이 삭제 뒤에 다시 저장되어서는 안 된다(MUST NOT). 삭제가 실패하면 실패 안내를 보여 주고 다시 시도할 수 있어야 한다.

#### Scenario: 삭제 후 첫 사용 상태
- **WHEN** 과목·덱·카드와 판정 기록이 있는 상태에서 전체 삭제를 끝낸다
- **THEN** 홈에 첫 사용 안내가 보이고, `bq:` 키는 새로 만든 `bq:meta`(알림 기록 없음)만 남는다

#### Scenario: 저장 대기 중 삭제
- **WHEN** 카드를 편집한 직후(저장 대기 중) 설정에서 전체 삭제를 끝내고 잠시 기다린다
- **THEN** 편집했던 카드가 저장소에 다시 생기지 않는다

#### Scenario: 삭제 실패
- **WHEN** 저장소 전체 삭제가 실패한다
- **THEN** 삭제하지 못했다는 안내와 다시 시도 동작이 보이고, 앱은 막다른 화면이 되지 않는다

#### Scenario: 삭제 후 재실행
- **WHEN** 전체 삭제 뒤 앱을 다시 연다
- **THEN** 과목·덱·카드가 없는 첫 사용 상태로 열린다

### Requirement: 복습 알림 항목 노출
알림 플래그가 켜져 있고, 알림 템플릿 코드가 설정되어 있고, 기기가 알림 동의 요청을 지원할 때만 설정 화면은 '복습 알림' 항목을 보여 주어야 한다(SHALL). 조건 중 하나라도 맞지 않으면 항목을 보여 주지 않는다. 설정 화면을 연 것만으로 동의 요청을 호출해서는 안 된다(MUST NOT).

#### Scenario: 플래그 off
- **WHEN** 알림 플래그를 지정하지 않은 빌드로 설정 화면을 연다
- **THEN** '복습 알림' 항목이 없다

#### Scenario: 미지원 기기
- **WHEN** 알림 플래그를 켰지만 동의 요청을 지원하지 않는 환경에서 설정 화면을 연다
- **THEN** '복습 알림' 항목이 없다

#### Scenario: 화면 진입만으로는 요청하지 않음
- **WHEN** 알림 플래그를 켠 빌드로 설정 화면을 연다
- **THEN** 동의 요청이 호출되지 않는다

### Requirement: 복습 알림 상태와 재요청
'복습 알림' 항목은 알림 동의 기록에 따라 현재 상태를 받는 중, 받지 않음, 아직 정하지 않음 중 하나로 보여 주어야 한다(SHALL). 받는 중이 아니면 "알림 받기" 동작을 제공하고, 누르면 동의를 요청해 결과를 학습 완료 화면과 같은 방식으로 기록한다. 요청이 오류로 끝나면 기록을 바꾸지 않고 실패 안내를 보여 준다.

#### Scenario: 거부한 사용자의 재요청 (N-06)
- **WHEN** 알림을 거부한 기록이 있는 상태에서 설정의 "알림 받기"를 누르고 동의한다
- **THEN** 알림 기록이 동의함으로 바뀌고 동의 시각이 있으며, 항목 상태가 받는 중으로 바뀐다

#### Scenario: 받는 중
- **WHEN** 동의 기록이 있는 상태에서 설정 화면을 연다
- **THEN** 항목 상태가 받는 중이고 "알림 받기" 동작이 없다

#### Scenario: 재요청 오류
- **WHEN** 거부 기록이 있는 상태에서 "알림 받기"를 눌렀는데 요청이 오류를 알린다
- **THEN** 알림 기록은 거부 그대로이고 실패 안내가 보인다
