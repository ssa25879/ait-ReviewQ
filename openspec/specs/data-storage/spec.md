# data-storage Specification

## Purpose

복습큐의 모든 학습 데이터를 기기 로컬 저장소에 문자열로 저장·조회하는 방법과 키 체계, 그리고 앱 설치 단위 메타데이터(Meta)의 초기화·영속 규칙을 정의한다.

## Requirements

### Requirement: 여러 키 일괄 조회
시스템은 키 목록을 받아 각 키의 저장 문자열을 키별로 돌려주어야 한다(SHALL). 저장되지 않은 키의 값은 `null`이어야 한다. 반환 결과에는 요청한 모든 키가 포함되어야 한다.

#### Scenario: 일부 키만 저장된 상태에서 조회
- **WHEN** `bq:meta`만 저장된 상태에서 `bq:meta`와 `bq:subjects`를 함께 조회한다
- **THEN** `bq:meta`는 저장된 문자열을, `bq:subjects`는 `null`을 돌려준다

#### Scenario: 일괄 조회를 지원하지 않는 토스 앱
- **WHEN** 토스 앱이 일괄 조회 API를 지원하지 않는 버전에서 여러 키를 조회한다
- **THEN** 키별 단건 조회 결과를 모아 일괄 조회와 같은 형태로 돌려준다

### Requirement: 여러 키 일괄 저장
시스템은 키와 문자열 값의 묶음을 받아 모두 저장해야 한다(SHALL). 저장이 실패하면 호출자에게 실패를 알려야 하며(MUST), 실패를 성공으로 보고해서는 안 된다.

#### Scenario: 저장 후 재조회
- **WHEN** `bq:subjects`와 `bq:decks`를 함께 저장한 뒤 같은 키를 조회한다
- **THEN** 저장한 문자열이 그대로 돌아온다

#### Scenario: 일괄 저장을 지원하지 않는 토스 앱
- **WHEN** 토스 앱이 일괄 저장 API를 지원하지 않는 버전에서 여러 키를 저장한다
- **THEN** 키별 단건 저장으로 모든 키를 저장한다

#### Scenario: 저장 실패
- **WHEN** 저장소가 쓰기 오류를 반환한다
- **THEN** 저장 호출은 오류로 끝나 호출자가 실패를 처리할 수 있다

### Requirement: 키 삭제와 전체 삭제
시스템은 단일 키를 삭제하는 기능과 앱의 저장 데이터를 전부 삭제하는 기능을 제공해야 한다(SHALL). 삭제한 키를 조회하면 `null`이어야 한다.

#### Scenario: 단일 키 삭제
- **WHEN** 저장된 `bq:decks`를 삭제한 뒤 조회한다
- **THEN** `null`을 돌려준다

#### Scenario: 전체 삭제
- **WHEN** 여러 키가 저장된 상태에서 전체 삭제한 뒤 그 키들을 조회한다
- **THEN** 모든 키가 `null`을 돌려준다

### Requirement: 저장 키 체계
시스템은 모든 저장 키에 `bq:` 접두사를 붙이고 다음 형식을 따라야 한다(SHALL): `bq:meta`, `bq:subjects`, `bq:decks`, 덱별 카드 `bq:cards:{deckId}`, 월별 리뷰 로그 `bq:logs:{YYYY-MM}`, 직전 정상본 `bq:backup:last`.

#### Scenario: 덱별 카드 키
- **WHEN** deckId가 `d1`인 덱의 카드 키를 만든다
- **THEN** 키는 `bq:cards:d1`이다

#### Scenario: 월별 로그 키
- **WHEN** 날짜 `2026-10-26`의 리뷰 로그 키를 만든다
- **THEN** 키는 `bq:logs:2026-10`이다

### Requirement: 최초 실행 시 Meta 생성
`bq:meta`가 없을 때 앱이 시작되면, 시스템은 `schemaVersion` 2, 기기 로컬 날짜 기준 오늘(`YYYY-MM-DD`)의 `lastOpenedDate`, 새로 생성한 `installId`를 가지고 알림 동의 기록은 없는 Meta를 만들어 `bq:meta`에 JSON 문자열로 저장해야 한다(SHALL).

#### Scenario: 빈 저장소에서 시작
- **WHEN** 저장소가 비어 있는 상태에서 2026-10-26에 앱이 시작된다
- **THEN** `bq:meta`에 `schemaVersion` 2, `lastOpenedDate` `2026-10-26`, 비어 있지 않은 `installId`가 저장되고 `notification`은 없다

### Requirement: 재실행 시 Meta 유지
`bq:meta`가 이미 있으면, 시스템은 앱 시작 시 저장된 Meta를 불러와야 하며(SHALL) 새 `installId`를 만들거나 `installId`를 덮어써서는 안 된다(MUST NOT). `schemaVersion`은 Meta 버전 올림으로만 바뀐다. `lastOpenedDate`는 날짜 규칙(시계 되돌림 판정)에 따라서만, 알림 동의 기록은 동의 결과로만 갱신한다. 한 항목을 갱신할 때 다른 항목의 저장 값을 잃어서는 안 된다(MUST NOT).

#### Scenario: 앱 재실행
- **WHEN** 첫 실행으로 Meta가 저장된 뒤 앱을 다시 시작한다
- **THEN** 첫 실행 때와 같은 `installId`를 가진 Meta를 불러온다

#### Scenario: 다음 날 재실행
- **WHEN** 2026-10-25에 저장된 v2 Meta가 있는 상태에서 2026-10-26에 앱을 시작한다
- **THEN** `bq:meta`의 `installId`·`schemaVersion`은 그대로이고 `lastOpenedDate`는 `2026-10-26`으로 저장된다

#### Scenario: 동의 기록 후 날짜 갱신
- **WHEN** 알림 동의 기록이 저장된 뒤 다음 날 앱으로 돌아와 `lastOpenedDate`가 갱신된다
- **THEN** `bq:meta`에 알림 동의 기록과 새 `lastOpenedDate`가 함께 남아 있다

### Requirement: 고유 식별자 생성
시스템은 데이터 항목과 설치 식별자에 쓸 비어 있지 않은 문자열 id를 생성해야 한다(SHALL). 플랫폼 표준 UUID 생성기를 쓸 수 없는 환경에서도 id를 생성해야 한다(MUST).

#### Scenario: 연속 생성
- **WHEN** id를 연속으로 여러 번 생성한다
- **THEN** 생성된 id는 모두 비어 있지 않고 서로 다르다

#### Scenario: UUID 생성기 미지원 환경
- **WHEN** 플랫폼 표준 UUID 생성기를 쓸 수 없는 환경에서 id를 생성한다
- **THEN** 대체 방식으로 비어 있지 않은 id를 돌려준다

### Requirement: 앱 데이터 로드
앱이 시작되면 시스템은 과목 목록, 덱 목록, 그리고 덱 목록에 있는 각 덱의 카드 목록을 저장소에서 불러와야 한다(SHALL). 저장된 값이 없는 키는 빈 목록으로 본다. 저장된 값이 형식 검증(data-recovery "저장 데이터 형식 검증")을 통과하지 못하면 덮어쓰지 않고, 손상된 키 목록과 함께 로드 실패로 알려야 한다(MUST).

#### Scenario: 첫 실행
- **WHEN** 저장소에 과목·덱·카드 키가 하나도 없는 상태에서 앱이 시작된다
- **THEN** 과목·덱·카드가 모두 빈 상태로 로드된다

#### Scenario: 재실행
- **WHEN** 과목 1개, 덱 2개, 덱별 카드가 저장된 뒤 앱을 다시 시작한다
- **THEN** 같은 과목·덱·카드가 로드된다

#### Scenario: 손상된 카드 키
- **WHEN** 한 덱의 카드 키 값이 JSON이 아니다
- **THEN** 로드가 실패로 끝나고 실패 결과에 그 카드 키가 들어 있으며 그 키의 저장 값은 바뀌지 않는다

#### Scenario: 형식이 틀린 덱 목록
- **WHEN** 덱 목록 키가 JSON 목록이지만 한 덱의 `name`이 31자다
- **THEN** 로드가 실패로 끝나고 실패 결과에 덱 목록 키가 들어 있다

### Requirement: 변경 키 지연 일괄 저장
데이터가 바뀌면 시스템은 바뀐 키만 모아 마지막 변경 후 일정 시간(400ms) 동안 추가 변경이 없을 때 한 번에 저장해야 한다(SHALL). 그 사이에 같은 키가 여러 번 바뀌면 마지막 값만 저장한다. 바뀌지 않은 키는 저장하지 않아야 한다(MUST NOT).

#### Scenario: 연속 편집
- **WHEN** 같은 덱의 카드를 100ms 간격으로 세 번 수정한다
- **THEN** 마지막 수정 400ms 후 해당 덱의 카드 키 하나만 마지막 상태로 한 번 저장된다

#### Scenario: 다른 키는 저장하지 않음
- **WHEN** 덱 A의 카드만 수정한다
- **THEN** 저장되는 키는 덱 A의 카드 키뿐이다

### Requirement: 삭제된 키 정리
덱이 삭제되면 시스템은 그 덱의 카드 키를 저장소에서 삭제해야 한다(SHALL). 같은 지연 저장 주기에서 처리한다.

#### Scenario: 과목 연쇄 삭제 후 저장소
- **WHEN** 덱 2개를 가진 과목을 삭제하고 지연 저장이 끝난다
- **THEN** 저장소의 과목·덱 목록에서 해당 항목이 빠지고 두 덱의 카드 키는 조회 시 `null`이다

### Requirement: 백그라운드 전환 시 즉시 저장
앱이 백그라운드로 전환되면 시스템은 지연 중인 저장을 기다리지 않고 즉시 실행해야 한다(SHALL).

#### Scenario: 편집 직후 앱 전환
- **WHEN** 카드를 수정하고 400ms가 지나기 전에 앱이 백그라운드로 전환된다
- **THEN** 지연을 기다리지 않고 수정 내용이 저장된다

### Requirement: 저장 실패 시 변경 보존
저장이 실패하면 시스템은 저장하지 못한 변경을 버리지 않고 보관했다가 다음 저장 때 함께 저장해야 한다(SHALL). 그 사이 같은 키가 다시 바뀌면 최신 값을 저장한다.

#### Scenario: 실패 후 다음 저장
- **WHEN** 덱 A 카드 키 저장이 실패한 뒤 덱 B의 카드를 수정하고 저장이 성공한다
- **THEN** 덱 A와 덱 B의 카드 키가 모두 최신 값으로 저장된다

### Requirement: 리뷰 로그 월별 저장
시스템은 판정 기록을 판정일이 속한 달의 키(`bq:logs:{YYYY-MM}`)에 저장해야 한다(SHALL). 기록이 추가된 달의 키만 저장하고, 다른 달의 키는 저장하지 않는다.

#### Scenario: 이번 달 기록 추가
- **WHEN** 2026-10-26에 판정해 기록이 1건 추가된다
- **THEN** `bq:logs:2026-10`만 저장되고 다른 로그 키는 저장되지 않는다

### Requirement: 리뷰 로그 로드
앱이 시작되면 시스템은 기기 로컬 날짜 기준 이번 달과 지난달의 로그 키를 불러와야 한다(SHALL). 값이 없는 키는 빈 목록으로 보고, 형식 검증을 통과하지 못하면 덮어쓰지 않고 손상된 키 목록과 함께 로드 실패로 알려야 한다(MUST).

#### Scenario: 연초 로드
- **WHEN** 2027-01-05에 앱이 시작된다
- **THEN** `bq:logs:2027-01`과 `bq:logs:2026-12`를 불러온다

#### Scenario: 재실행 후 기록 유지
- **WHEN** 판정 기록 2건을 남기고 앱을 다시 시작한다
- **THEN** 같은 기록 2건이 로드된다

#### Scenario: 날짜 형식이 틀린 기록
- **WHEN** 이번 달 로그 키의 한 기록의 `date`가 `2026/10/26`이다
- **THEN** 로드가 실패로 끝나고 실패 결과에 그 로그 키가 들어 있다

### Requirement: 판정 즉시 저장
판정이 반영되면 시스템은 지연 저장을 기다리지 않고 대기 중인 모든 변경을 즉시 저장해야 한다(SHALL). 판정 직후 앱이 강제 종료되어도 판정이 남게 하기 위해서다.

#### Scenario: 판정 직후 종료 (D-01)
- **WHEN** 카드를 판정하고 400ms가 지나기 전에 저장 상태를 확인한다
- **THEN** 카드 일정과 판정 기록이 이미 저장소에 있다

### Requirement: Meta 버전 올림
앱 시작 시 저장된 Meta의 `schemaVersion`이 현재 버전(2)보다 낮으면 시스템은 버전별 변환을 순서대로 적용해 현재 버전으로 올리고 `bq:meta`에 저장해야 한다(SHALL). v1 → v2 변환은 알림 동의 기록을 비운 채 버전만 올린다. 다른 키는 바꾸지 않는다.

#### Scenario: v1 Meta 올림 (D-05)
- **WHEN** `schemaVersion` 1 Meta와 과목·덱·카드가 저장된 상태에서 앱을 시작한다
- **THEN** `bq:meta`가 `schemaVersion` 2, 같은 `installId`, 알림 기록 없음으로 저장되고 과목·덱·카드는 그대로 보인다
