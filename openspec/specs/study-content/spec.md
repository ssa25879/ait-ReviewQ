# study-content Specification

## Purpose

사용자가 학습 내용을 과목 > 덱 > 카드의 3단 계층으로 만들고 고치고 옮기고 지우는 규칙, 입력 제한, 연쇄 삭제, 신규 카드의 초기 복습 일정을 정의한다.

## Requirements

### Requirement: 이름 입력 제한
시스템은 과목명과 덱명의 앞뒤 공백을 제거한 뒤 1자 이상 30자 이하일 때만 저장해야 한다(SHALL). 조건을 벗어나면 저장하지 않고 위반 사유를 돌려주어야 한다(MUST). 저장되는 이름은 앞뒤 공백을 제거한 값이다.

#### Scenario: 공백만 입력
- **WHEN** 과목명으로 공백 세 칸을 입력한다
- **THEN** 과목이 만들어지지 않고 빈 값 사유가 돌아온다

#### Scenario: 최대 길이
- **WHEN** 앞뒤 공백을 제거하면 정확히 30자인 덱명을 입력한다
- **THEN** 덱이 만들어지고 이름은 앞뒤 공백이 제거된 30자다

#### Scenario: 최대 길이 초과
- **WHEN** 31자 과목명을 입력한다
- **THEN** 과목이 만들어지지 않고 길이 초과 사유가 돌아온다

### Requirement: 카드 입력 제한
시스템은 카드의 질문과 정답이 각각 앞뒤 공백 제거 후 1자 이상 500자 이하일 때만 저장해야 한다(SHALL). 내부 줄바꿈은 허용한다. 조건을 벗어나면 저장하지 않고 어느 항목이 왜 위반했는지 돌려주어야 한다(MUST). 글자 수는 유니코드 문자(코드 포인트) 단위로 센다.

#### Scenario: 정답이 비어 있음
- **WHEN** 질문은 채우고 정답은 비운 채 카드를 저장한다
- **THEN** 카드가 저장되지 않고 정답 항목의 빈 값 사유가 돌아온다

#### Scenario: 줄바꿈이 있는 질문
- **WHEN** 줄바꿈이 포함된 질문과 정답으로 카드를 저장한다
- **THEN** 줄바꿈이 유지된 채 저장된다

#### Scenario: 이모지 포함 길이
- **WHEN** 이모지 500개로 된 질문을 저장한다
- **THEN** 500자로 계산되어 저장된다

### Requirement: 과목 관리
시스템은 과목의 생성, 이름 변경, 삭제를 제공해야 한다(SHALL). 생성 시 새 id와 생성·수정 시각을 부여하고, 이름 변경 시 수정 시각을 갱신해야 한다.

#### Scenario: 과목 생성
- **WHEN** 이름 "영어"로 과목을 만든다
- **THEN** 과목 목록에 이름 "영어"인 과목이 추가되고 생성 시각과 수정 시각이 같다

#### Scenario: 과목 이름 변경
- **WHEN** 과목 이름을 "영단어"로 바꾼다
- **THEN** 이름이 바뀌고 수정 시각이 갱신되며 생성 시각은 유지된다

### Requirement: 덱 관리
시스템은 과목 하위에 덱을 생성하고, 이름을 변경하고, 다른 과목으로 이동하고, 삭제하는 기능을 제공해야 한다(SHALL). 존재하지 않는 과목에 덱을 만들거나 옮겨서는 안 된다(MUST NOT). 덱을 이동해도 덱의 카드와 카드 일정은 바뀌지 않아야 한다.

#### Scenario: 덱 이동
- **WHEN** 카드 3장이 있는 덱을 다른 과목으로 옮긴다
- **THEN** 덱의 소속 과목이 바뀌고 카드 3장과 각 카드의 일정은 그대로다

#### Scenario: 없는 과목으로 이동
- **WHEN** 존재하지 않는 과목 id로 덱을 옮긴다
- **THEN** 상태가 바뀌지 않는다

### Requirement: 카드 관리
시스템은 덱 하위에 카드를 생성하고, 질문·정답을 수정하고, 삭제하는 기능을 제공해야 한다(SHALL). 질문·정답을 수정해도 카드의 복습 일정은 바뀌지 않아야 한다(MUST NOT).

#### Scenario: 카드 수정
- **WHEN** stage 3인 카드의 정답을 수정한다
- **THEN** 정답과 수정 시각이 바뀌고 stage·다음 복습일은 그대로다

#### Scenario: 카드 삭제
- **WHEN** 카드 2장이 있는 덱에서 한 장을 삭제한다
- **THEN** 덱에 나머지 한 장만 남는다

### Requirement: 신규 카드 초기 일정
새로 만든 카드는 stage 0, 다음 복습일은 생성한 날(기기 로컬 날짜), 직전 복습일 없음, 복습·실패 횟수 0, 현재 스케줄러의 알고리즘 id와 버전을 가져야 한다(SHALL).

#### Scenario: 카드 생성 직후 일정
- **WHEN** 2026-10-26에 카드를 만든다
- **THEN** 카드의 stage는 0, 다음 복습일은 `2026-10-26`, 직전 복습일은 없음, 복습 횟수와 실패 횟수는 0, 알고리즘은 `fixed-interval` 버전 1이다

### Requirement: 연쇄 삭제
과목을 삭제하면 시스템은 그 과목의 모든 덱과 그 덱들의 모든 카드를 함께 삭제해야 한다(SHALL). 덱을 삭제하면 그 덱의 모든 카드를 함께 삭제해야 한다. 다른 과목·덱의 데이터는 바뀌지 않아야 한다(MUST NOT).

#### Scenario: 과목 삭제
- **WHEN** 덱 2개(각 카드 있음)를 가진 과목 A와 덱 1개를 가진 과목 B가 있을 때 과목 A를 삭제한다
- **THEN** 과목 A, 그 덱 2개와 카드가 모두 사라지고 과목 B와 그 덱·카드는 그대로다

#### Scenario: 덱 삭제
- **WHEN** 카드 5장이 있는 덱을 삭제한다
- **THEN** 덱과 카드 5장이 사라지고 같은 과목의 다른 덱은 그대로다
