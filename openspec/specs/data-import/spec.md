# data-import Specification

## Purpose
사용자가 내보낸 백업 파일로 학습 데이터를 되살리는 기능의 입력 방식, 검증, 확인 절차, 전체 교체와 실패 처리를 정의한다.

## Requirements

### Requirement: 가져오기 진입과 입력
설정의 백업 섹션은 "백업 가져오기" 동작을 제공해야 한다(SHALL). 누르면 백업 코드나 백업 내용을 붙여넣는 입력란과, 백업 파일을 고르는 동작을 함께 보여 준다. 입력란에는 백업 코드만, 코드가 든 공유 메시지 전체, 또는 내보낸 JSON 내용을 붙여넣을 수 있다. 입력만으로는 저장 데이터를 바꾸지 않는다.

#### Scenario: 파일 선택
- **WHEN** "백업 가져오기"에서 내보내기 파일을 고른다
- **THEN** 파일 내용을 읽어 검증 단계로 넘어가고 저장 데이터는 그대로다

#### Scenario: 붙여넣기
- **WHEN** 입력란에 내보낸 백업 내용을 붙여넣고 불러오기를 누른다
- **THEN** 붙여넣은 내용으로 검증 단계로 넘어간다

#### Scenario: 공유 메시지 붙여넣기
- **WHEN** 안내 문구와 백업 코드가 함께 든 공유 메시지 전체를 붙여넣고 불러오기를 누른다
- **THEN** 메시지에서 코드를 찾아 풀고 검증 단계로 넘어간다

### Requirement: 백업 검증과 요약
시스템은 불러온 내용이 내보내기 형식 검증을 통과하고, 모든 덱의 과목과 모든 카드의 덱이 문서 안에 있을 때만 가져오기를 허용해야 한다(SHALL). 통과하면 확인 팝업에 과목·단원·카드·학습 기록 수와 내보낸 날짜를 보여 준다. JSON이 아니거나, 백업 코드를 풀 수 없거나, 검증에 실패하거나, 이 앱보다 새 형식 버전·데이터 버전이면 이유를 알리고 팝업을 열지 않는다(MUST NOT).

#### Scenario: 정상 백업
- **WHEN** 과목 2·단원 3·카드 10장·기록 4건이 든 백업을 불러온다
- **THEN** 확인 팝업에 "과목 2개, 단원 3개, 카드 10장, 학습 기록 4건"과 내보낸 날짜가 보인다

#### Scenario: 잘못된 내용
- **WHEN** JSON이 아닌 글이나 형식이 틀린 문서를 불러온다
- **THEN** 백업 파일이 아니라는 안내가 보이고 팝업은 열리지 않는다

#### Scenario: 잘린 백업 코드
- **WHEN** 끝부분이 잘린 백업 코드를 불러온다
- **THEN** 코드가 올바르지 않으니 전체를 복사했는지 확인하라는 안내가 보이고 팝업은 열리지 않는다

#### Scenario: 참조 불일치
- **WHEN** 덱이 가리키는 과목이 문서에 없는 백업을 불러온다
- **THEN** 백업 내용이 맞지 않는다는 안내가 보이고 팝업은 열리지 않는다

#### Scenario: 새 버전 백업
- **WHEN** 형식 버전이나 데이터 버전이 이 앱보다 높은 백업을 불러온다
- **THEN** 앱을 업데이트한 뒤 가져오라는 안내가 보이고 팝업은 열리지 않는다

### Requirement: 전체 교체 실행
최종 확인을 받으면 시스템은 지금 데이터를 보관 키에 내보내기 형식으로 먼저 저장한 뒤, 과목·덱·카드·학습 기록을 백업 내용으로 바꾸고 홈을 열어야 한다(SHALL). 지금 데이터에만 있던 덱의 카드 키와 학습 기록 키는 지운다. Meta(설치 식별자·알림 동의 기록)는 유지한다. 저장 대기 중이던 변경이 교체 뒤에 다시 저장되어서는 안 된다(MUST NOT).

#### Scenario: 교체 후 상태
- **WHEN** 과목 1개가 있는 상태에서 과목 2개짜리 백업을 가져온다
- **THEN** 홈과 과목 목록에 백업의 과목 2개만 보이고, 카드의 다음 복습일과 통계의 학습 기록이 백업과 같다

#### Scenario: 이전 데이터 보관과 Meta 유지
- **WHEN** 알림 동의 기록이 있는 상태에서 가져오기를 끝낸다
- **THEN** 보관 키에 가져오기 전 데이터가 내보내기 형식으로 있고, `bq:meta`의 설치 식별자와 알림 동의 기록은 그대로다

#### Scenario: 저장 대기 중 가져오기
- **WHEN** 카드를 편집한 직후(저장 대기 중) 가져오기를 끝내고 잠시 기다린다
- **THEN** 편집한 카드가 저장소에 다시 생기지 않는다

### Requirement: 가져오기 실패
보관이나 교체 중 저장이 실패하면 시스템은 실패 안내와 다시 시도할 동작을 보여 주고, 저장소의 실제 상태를 다시 읽어 화면에 반영해야 한다(SHALL). 보관 저장이 실패하면 교체를 시작하지 않는다(MUST NOT).

#### Scenario: 보관 실패
- **WHEN** 이전 데이터 보관 저장이 실패한다
- **THEN** 가져오지 못했다는 안내가 보이고 과목·덱·카드는 가져오기 전과 같다

### Requirement: 가져오기 확인 팝업
검증을 통과하면 시스템은 바로 확인 팝업을 열어 요약과 함께 지금의 과목·단원·카드·학습 기록이 백업 내용으로 바뀐다는 경고를 보여 주고, [취소 | 바꾸기]를 제공해야 한다(SHALL). "취소"나 팝업 닫기는 저장 데이터를 바꾸지 않는다. "바꾸기"는 전체 교체를 실행한다. 진행 중에는 다시 누를 수 없다.

#### Scenario: 취소
- **WHEN** 확인 팝업에서 "취소"를 누른다
- **THEN** 팝업이 닫히고 저장 데이터가 그대로이며 설정 화면에 머문다

#### Scenario: 바꾸기
- **WHEN** 확인 팝업에서 "바꾸기"를 누른다
- **THEN** 백업 내용으로 교체되고 홈이 열린다
