# Spec Delta

## ADDED Requirements

### Requirement: 앱 데이터 로드
앱이 시작되면 시스템은 과목 목록, 덱 목록, 그리고 덱 목록에 있는 각 덱의 카드 목록을 저장소에서 불러와야 한다(SHALL). 저장된 값이 없는 키는 빈 목록으로 본다. 저장된 값이 JSON으로 읽히지 않으면 덮어쓰지 않고 로드 실패로 알려야 한다(MUST).

#### Scenario: 첫 실행
- **WHEN** 저장소에 과목·덱·카드 키가 하나도 없는 상태에서 앱이 시작된다
- **THEN** 과목·덱·카드가 모두 빈 상태로 로드된다

#### Scenario: 재실행
- **WHEN** 과목 1개, 덱 2개, 덱별 카드가 저장된 뒤 앱을 다시 시작한다
- **THEN** 같은 과목·덱·카드가 로드된다

#### Scenario: 손상된 카드 키
- **WHEN** 한 덱의 카드 키 값이 JSON이 아니다
- **THEN** 로드가 실패로 끝나고 그 키의 저장 값은 바뀌지 않는다

### Requirement: 변경 키 지연 일괄 저장
데이터가 바뀌면 시스템은 바뀐 키만 모아 마지막 변경 후 일정 시간(400ms) 동안 추가 변경이 없을 때 한 번에 저장해야 한다(SHALL). 그 사이에 같은 키가 여러 번 바뀌면 마지막 값만 저장한다. 바뀌지 않은 키는 저장하지 않아야 한다(MUST NOT).

#### Scenario: 연속 편집
- **WHEN** 같은 덱의 카드를 100ms 간격으로 세 번 수정한다
- **THEN** 마지막 수정 400ms 후 해당 덱의 카드 키 하나만 마지막 상태로 한 번 저장된다

#### Scenario: 다른 키는 저장하지 않음
- **WHEN** 덱 A의 카드만 수정한다
- **THEN** 저장되는 키는 덱 A의 카드 키뿐이다

### Requirement: 삭제된 키 정리
덱이 삭제되면 시스템은 그 덱의 카드 키를 저장소에서 삭제해야 한다(SHALL). 같은 지연 저장 주기에서 처리한다.

#### Scenario: 과목 연쇄 삭제 후 저장소
- **WHEN** 덱 2개를 가진 과목을 삭제하고 지연 저장이 끝난다
- **THEN** 저장소의 과목·덱 목록에서 해당 항목이 빠지고 두 덱의 카드 키는 조회 시 `null`이다

### Requirement: 백그라운드 전환 시 즉시 저장
앱이 백그라운드로 전환되면 시스템은 지연 중인 저장을 기다리지 않고 즉시 실행해야 한다(SHALL).

#### Scenario: 편집 직후 앱 전환
- **WHEN** 카드를 수정하고 400ms가 지나기 전에 앱이 백그라운드로 전환된다
- **THEN** 지연을 기다리지 않고 수정 내용이 저장된다

### Requirement: 저장 실패 시 변경 보존
저장이 실패하면 시스템은 저장하지 못한 변경을 버리지 않고 보관했다가 다음 저장 때 함께 저장해야 한다(SHALL). 그 사이 같은 키가 다시 바뀌면 최신 값을 저장한다.

#### Scenario: 실패 후 다음 저장
- **WHEN** 덱 A 카드 키 저장이 실패한 뒤 덱 B의 카드를 수정하고 저장이 성공한다
- **THEN** 덱 A와 덱 B의 카드 키가 모두 최신 값으로 저장된다
