# Design

## Context

- 가져오기(`Settings.tsx`의 `ImportPanel`)는 불러오기 → 화면 안 요약 → "이 백업으로 바꾸기" → 확인 2번 흐름이다. `ConfirmDialog`(`components/Dialog.tsx`)는 `detail: string` 한 줄만 받는다.
- 홈(`screens/Home`)은 제목 "오늘 복습", 요약 카드, 과목별 목록, 맨 아래 통계·설정 행, 하단 고정 버튼([과목·덱 관리 | 학습 시작] 등)으로 되어 있다. 아이콘은 `components/icons.tsx`의 SVG 7종(꺾쇠·닫기·검색·더보기)뿐이다. 이모지는 Tossface 배선이 없어 쓰지 않는다(AGENTS.md 하드 규칙).
- "덱"은 `messages.ts`(18곳)와 화면 파일(SubjectList 7, Dialog 2, DeckDetail·CardBulk·StudySession·DemoSection 각 1)에 있다. "덱"과 "단원" 모두 받침으로 끝나 조사(이/을/과/으로)를 그대로 둘 수 있다.
- 홈 스펙은 진입 직후 대화상자·바텀시트를 금지한다. 경로는 해시 `Route` 유니언이고 seed로 상위 화면을 채운다. 시작 로드는 `bootstrap.startApp()` → `ContentProvider`가 받는다.
- CDP 스크립트 10종은 저장소를 비운 뒤 첫 화면이 홈이라고 가정한다.

## Goals / Non-Goals

**Goals:**
- 홈이 앱의 첫 화면임이 한눈에 보이고, 통계·과목 관리·설정에 바로 갈 수 있다.
- 처음 연 사용자가 1분 안에 원리를 알고 시작한다.
- 백업 가져오기를 한 번의 선택으로 끝낸다.

**Non-Goals:**
- 하단 탭 바, 종료 확인, 저장 형식 변경.

## Decisions

1. **가져오기 확인은 `ConfirmDialog` 한 번.** `detail`을 `ReactNode`로 넓혀 요약(수치)·내보낸 날짜·경고 세 줄을 담는다. 제목 "이 백업으로 바꿀까요?", 확인 "바꾸기", 취소는 팝업 닫기. 검증 통과 즉시 팝업을 연다(붙여넣기·파일 선택 모두). 화면 안 요약 블록·"이 백업으로 바꾸기" 버튼·2단계는 지운다. 교체 중에는 팝업을 닫고 상태 문구("바꾸는 중이에요")를 보여 연타를 막는다.
2. **홈 머리말·타일(`Home.tsx`).**
   - 제목 위에 브랜드색(`#0F8B7A`, 토큰 `--color-brand-accent`로 추가) 작은 글씨 "복습큐 · 10월 27일 (월)"을 둔다. 제목 "오늘 복습"은 유지한다.
   - 요약(또는 빈 상태 안내) 바로 아래에 3칸 타일: 통계(`ChartIcon`)·과목 관리(`BookIcon`)·설정(`GearIcon`). 아이콘은 `icons.tsx`에 `currentColor` SVG로 더한다. 타일은 캔버스 배경, 둥근 모서리 16px, 높이 76px 이상, 이름 15px.
   - 맨 아래 통계·설정 행을 지운다. 하단 고정 버튼: 첫 사용 → "과목·단원 만들기", 오늘 복습 있음 → "학습 시작", 그 밖 → 없음(빈 여백도 두지 않음).
3. **용어.** 화면 문구의 "덱"을 "단원"으로 바꾼다(`messages.ts`, 화면 JSX·aria-label 포함). `messages.ts`의 키 이름(`deckName` 등), 타입·변수·저장 키는 그대로다. CDP 스크립트의 문구 기대값도 같이 바꾼다.
4. **가이드(`screens/Guide/Guide.tsx`, 경로 `#/guide`, seed [home]).**
   - 3장: ① "외울 내용을 카드로 만들어요"(질문·정답 카드 예시) ② "복습할 날이 되면 홈에 모여요"(오늘 복습 요약 예시) ③ "기억할수록 간격이 늘어나요"(1·3·7·14·30·60일 칩, 기억 못 함이면 처음부터). 진행 표시 "1 / 3", 하단 고정 버튼 "다음", 위쪽 오른쪽 "건너뛰기"(마지막 장 제외).
   - 마지막 장: 카드가 없으면 [직접 만들기 | 예시 카드로 시작(주)], 있으면 [확인]. 예시 카드 만들기는 홈의 예시 덱 로직을 `domain/sampleDeck.ts`의 `sampleDeckActions()`로 옮겨 함께 쓴다.
   - 끝내기 공통: 본 기록 저장 후 건너뛰기·확인·예시 → `back()`, 직접 만들기 → `replace(subjects)`. 처음 실행은 [home, guide]라 `back()`이 홈, 다시 보기는 [home, settings, guide]라 설정으로 돌아간다.
   - 본 기록: 키 `bq:guide`(값 `"true"`). `startApp()`이 함께 읽어 `AppStart.ok.guideSeen`으로 넘기고, `ContentProvider`가 `guideSeen`·`markGuideSeen()`을 컨텍스트로 제공한다. 쓰기 실패는 기록만 남기고 흐름을 막지 않는다(다음 실행에 다시 보일 뿐).
   - 자동 열기: `App`이 **앱 시작 후 첫 ready 때 한 번만** 판단한다(`useRef`). `!guideSeen && 카드 0장 && 경로가 홈`이면 `navigate({ name: 'guide' })`로 홈 위에 쌓는다(`replace`면 아래에 홈이 없어 끝낼 때 앱을 벗어난다). 그래서 가이드에서 뒤로가기로 홈에 와도 다시 열리지 않고, 전체 삭제 후 다시 불러올 때도 열리지 않는다(다음 실행 때 열림).
   - 설정의 데이터 섹션 위에 "사용 방법" 섹션과 "사용 방법 보기" 버튼.
5. **검증.**
   - 단위 테스트: 라우터 `guide`, `startApp`이 `guideSeen`을 읽는지(`loadApp` 경로는 그대로이므로 bootstrap 대신 키 읽기 함수 단위로).
   - CDP: 새 `handoff/e2e/ux.mjs`(가이드 처음 실행·장 넘기기·건너뛰기·예시로 시작·직접 만들기·뒤로가기 후 재열림 없음·재실행 시 미노출·카드 있으면 미노출·설정에서 다시 보기·카드 있을 때 확인, 홈 머리말·타일 이동, 화면 전체에 "덱" 없음, 글자·터치). 기존 스크립트는 `localStorage.clear()` 뒤에 `bq:guide`를 넣도록 바꾸고(첫 화면 홈 가정 유지), "덱" 기대값을 "단원"으로, 가져오기 흐름을 팝업으로, 홈 하단 버튼 기대값을 새 구성으로 고친다(바꾼 줄은 보고에 적기).

## Risks / Trade-offs

- [하단에서 "과목 관리" 버튼이 빠져 기존 사용자가 헷갈릴 수 있다] → 같은 위치 대신 요약 바로 아래 타일로 더 크게 보인다. 출시 전이라 기존 사용자가 없다.
- [가이드 본 기록을 Meta가 아닌 별도 키에 둔다] → Meta 형식 버전을 올리지 않기 위해서다. 키가 없거나 깨져도 가이드가 한 번 더 보일 뿐 데이터에는 영향이 없다.
- [등록용 스크린샷·상세 설명에 "덱"과 옛 홈 화면이 남아 있다] → 출시 준비 단계에서 다시 캡처·작성한다.

## Migration Plan

- 저장 형식 변경 없음. 새 키 `bq:guide` 하나만 생긴다.
