# Spec Delta

## Purpose

사용자가 과목·덱·카드를 보고 만들고 고치고 지우는 화면에서 무엇을 보고 무엇을 할 수 있는지 정의한다. 입력 안내, 삭제 확인, 빈 상태·로딩·로드 실패 표시도 함께 정의한다.

## ADDED Requirements

### Requirement: 과목·덱 목록 표시
과목·덱 목록 화면은 과목마다 그 과목의 덱 이름과 덱별 카드 수를 보여 주어야 한다(SHALL). 덱을 누르면 덱 상세 화면으로 이동해야 한다.

#### Scenario: 덱별 카드 수
- **WHEN** 과목 "영어"에 카드 3장인 덱 "단어"와 카드 0장인 덱 "문법"이 있다
- **THEN** "영어" 아래에 "단어 3장", "문법 0장"이 보인다

#### Scenario: 덱 진입
- **WHEN** 덱 "단어"를 누른다
- **THEN** 덱 "단어"의 상세 화면으로 이동한다

### Requirement: 과목·덱 생성과 이름 변경
과목·덱 목록 화면에서 사용자는 과목을 만들고, 과목 아래에 덱을 만들고, 과목·덱의 이름을 바꿀 수 있어야 한다(SHALL). 이름이 입력 제한을 어기면 입력창 근처에 이유를 보여 주고 저장하지 않아야 한다(MUST). 같은 과목에 같은 이름의 덱이 이미 있으면 경고 문구를 보여 주되 저장은 허용한다.

#### Scenario: 빈 이름
- **WHEN** 과목 이름 입력창을 비운 채 저장을 누른다
- **THEN** 이름을 입력하라는 안내가 보이고 과목이 만들어지지 않는다

#### Scenario: 길이 초과
- **WHEN** 31자 덱 이름을 입력한다
- **THEN** 30자 이하로 입력하라는 안내가 보이고 저장 버튼으로 저장되지 않는다

#### Scenario: 중복 덱 이름
- **WHEN** 덱 "단어"가 있는 과목에 "단어"라는 덱을 하나 더 만든다
- **THEN** 같은 이름의 덱이 있다는 경고가 보이고, 저장하면 덱이 만들어진다

### Requirement: 덱 이동
사용자는 덱을 다른 과목으로 옮길 수 있어야 한다(SHALL). 옮길 과목은 현재 과목을 제외한 과목 목록에서 고른다. 다른 과목이 없으면 이동 기능을 쓸 수 없어야 한다.

#### Scenario: 다른 과목으로 이동
- **WHEN** 과목 "영어"의 덱 "단어"를 과목 "토익"으로 옮긴다
- **THEN** 목록에서 "단어"가 "토익" 아래에 같은 카드 수로 보인다

### Requirement: 삭제 확인
과목·덱·카드를 지우기 전에 시스템은 확인을 받아야 한다(SHALL). 확인 문구는 함께 지워지는 하위 항목의 수를 알려야 한다(MUST). 사용자가 취소하면 아무것도 지우지 않는다.

#### Scenario: 과목 삭제 확인
- **WHEN** 덱 2개와 카드 5장이 있는 과목의 삭제를 누른다
- **THEN** 덱 2개와 카드 5장이 함께 지워진다는 확인 문구가 보이고, 확인하면 과목이 목록에서 사라진다

#### Scenario: 삭제 취소
- **WHEN** 덱 삭제 확인에서 취소를 누른다
- **THEN** 덱과 카드가 그대로 남는다

### Requirement: 덱 상세
덱 상세 화면은 덱 이름, 카드 목록(질문 미리보기와 다음 복습일), 카드 추가 동작을 보여 주어야 한다(SHALL). 카드를 누르면 그 카드의 편집 화면으로 이동해야 한다. 카드가 없으면 빈 상태 안내와 카드 추가 동작을 함께 보여 주어야 한다(MUST).

#### Scenario: 카드 목록
- **WHEN** 카드 2장이 있는 덱의 상세 화면을 연다
- **THEN** 두 카드의 질문 미리보기와 다음 복습일이 보인다

#### Scenario: 빈 덱
- **WHEN** 카드가 없는 덱의 상세 화면을 연다
- **THEN** 카드가 없다는 안내와 카드 추가 동작이 보인다

### Requirement: 카드 작성·편집
카드 작성·편집 화면은 질문과 정답 입력란, 각 입력란의 글자 수와 최대 글자 수를 보여 주어야 한다(SHALL). 입력 제한을 어기면 어느 입력란이 왜 문제인지 보여 주고 저장하지 않아야 한다(MUST). 새 카드는 "저장"과 "저장 후 계속"을, 기존 카드는 "저장"과 "삭제"를 제공한다. "저장 후 계속"은 카드를 저장한 뒤 같은 덱의 빈 작성 화면을 유지한다.

#### Scenario: 글자 수 표시
- **WHEN** 질문란에 10자를 입력한다
- **THEN** 질문란에 "10/500"이 보인다

#### Scenario: 정답 누락
- **WHEN** 질문만 입력하고 저장을 누른다
- **THEN** 정답을 입력하라는 안내가 정답란에 보이고 카드가 저장되지 않는다

#### Scenario: 저장 후 계속
- **WHEN** 새 카드 작성 화면에서 질문과 정답을 입력하고 "저장 후 계속"을 누른다
- **THEN** 카드가 덱에 추가되고 입력란이 비워진 작성 화면이 유지된다

### Requirement: 로딩과 로드 실패 표시
저장 데이터를 불러오는 동안 시스템은 불러오는 중임을 알려야 한다(SHALL). 불러오기에 실패하면 실패 안내를 보여 주고 생성·수정·삭제 동작을 제공해서는 안 된다(MUST NOT). 손상된 데이터를 덮어쓰지 않기 위해서다.

#### Scenario: 로드 실패
- **WHEN** 저장된 카드 데이터가 손상되어 불러오기에 실패한다
- **THEN** 데이터를 불러오지 못했다는 안내가 보이고 추가·편집·삭제 버튼이 보이지 않는다

### Requirement: 재실행 후 유지
화면에서 만들고 고치고 지운 결과는 앱을 다시 실행한 뒤에도 그대로 보여야 한다(SHALL).

#### Scenario: 생성 후 재실행
- **WHEN** 과목 1개, 덱 1개, 카드 2장을 만들고 앱을 다시 연다
- **THEN** 같은 과목·덱·카드가 같은 내용으로 보인다

#### Scenario: 연쇄 삭제 후 재실행
- **WHEN** 덱과 카드가 있는 과목을 삭제하고 앱을 다시 연다
- **THEN** 그 과목과 덱·카드가 보이지 않는다
