# Spec Delta

## Purpose

저장된 데이터가 손상되었거나 저장소 호출이 실패했을 때, 시스템이 어떤 데이터를 손상으로 판정하고 사용자의 데이터를 잃지 않으면서 어떻게 앱을 다시 쓸 수 있게 하는지 정의한다.

## ADDED Requirements

### Requirement: 저장 데이터 형식 검증
앱이 시작되면 시스템은 불러온 과목·덱·카드·판정 기록·Meta 키의 값을 검증해야 한다(SHALL). 값이 JSON으로 읽히지 않거나, 목록이 아니거나, 항목 하나라도 필수 필드·타입·날짜 형식(`YYYY-MM-DD`)·문자열 길이 제한을 어기면 그 키 전체를 손상으로 판정한다. 손상으로 판정한 키의 저장 값은 사용자가 복구 동작을 고르기 전에는 바꾸어서는 안 된다(MUST NOT).

#### Scenario: 필드가 빠진 카드
- **WHEN** 한 덱의 카드 키가 JSON 목록이지만 그중 한 카드에 `schedule.dueDate`가 없다
- **THEN** 그 카드 키가 손상으로 판정되고 저장 값은 그대로 남는다

#### Scenario: 정상 데이터
- **WHEN** 모든 키가 형식에 맞는 상태로 앱이 시작된다
- **THEN** 손상 판정 없이 평소처럼 홈 화면이 보인다

### Requirement: 마지막 정상 백업
모든 키가 손상 없이 로드되면 시스템은 과목·덱·카드 전체를 백업 키(`bq:backup:last`)에 백업 날짜와 함께 저장해야 한다(SHALL). 같은 날짜의 백업이 이미 있으면 다시 저장하지 않는다. 손상된 키가 하나라도 있으면 백업을 갱신해서는 안 된다(MUST NOT).

#### Scenario: 하루 첫 실행
- **WHEN** 백업 날짜가 어제인 상태에서 정상 데이터로 앱을 시작한다
- **THEN** 백업이 오늘 날짜와 현재 과목·덱·카드로 바뀐다

#### Scenario: 손상 상태에서는 갱신하지 않음
- **WHEN** 카드 키 하나가 손상된 상태로 앱을 시작한다
- **THEN** 백업 키의 값은 바뀌지 않는다

### Requirement: 복구 화면
손상된 키가 있으면 시스템은 과목·덱·카드 편집 화면 대신 복구 화면을 보여 주어야 한다(SHALL). 복구 화면은 손상된 항목 수와 선택지를 보여 준다. 사용할 수 있는 백업이 있으면 백업 날짜와 과목·덱·카드 수를 함께 보여 주고 "백업으로 복구"를 제공한다. "손상 항목 빼고 열기"와 "다시 시도"는 항상 제공한다. 진입하자마자 대화상자를 띄우지 않는다.

#### Scenario: 백업이 있는 손상
- **WHEN** 카드 키 하나가 손상되었고 어제 날짜의 백업이 있다
- **THEN** 복구 화면에 손상 1건 안내, 백업 날짜와 수, 세 가지 선택지가 보이고 추가·편집·삭제 버튼은 보이지 않는다

#### Scenario: 백업이 없는 손상
- **WHEN** 카드 키 하나가 손상되었고 백업 키가 없다
- **THEN** "손상 항목 빼고 열기"와 "다시 시도"만 보인다

### Requirement: 손상 원본 격리
복구 동작이 손상된 키를 바꾸기 전에 시스템은 그 키의 원본 값을 격리 키(`bq:quarantine:{원래 키}`)에 먼저 저장해야 한다(SHALL). 격리 저장이 실패하면 원래 키를 바꾸지 않고 복구를 멈추고 실패를 안내해야 한다(MUST).

#### Scenario: 격리 후 변경 (D-04)
- **WHEN** 손상된 카드 키가 있는 상태에서 복구 동작을 고른다
- **THEN** `bq:quarantine:{그 카드 키}`에 원본 문자열이 그대로 저장된 뒤 원래 키가 바뀐다

#### Scenario: 격리 실패
- **WHEN** 격리 키 저장이 실패한다
- **THEN** 원래 키는 바뀌지 않고 복구 화면에 실패 안내가 보인다

### Requirement: 백업으로 복구
"백업으로 복구"를 고르면 시스템은 손상 키를 격리한 뒤 과목·덱·카드를 백업 내용으로 되돌리고 앱을 다시 불러와야 한다(SHALL). 손상된 판정 기록 키는 빈 목록으로 바꾼다. 손상되지 않은 판정 기록은 그대로 둔다.

#### Scenario: 백업 복구
- **WHEN** 백업에 과목 1개·덱 1개·카드 3장이 있고 그 덱의 카드 키가 손상된 상태에서 "백업으로 복구"를 고른다
- **THEN** 홈 화면이 열리고 과목 1개·덱 1개·카드 3장이 백업과 같은 내용과 다음 복습일로 보인다

### Requirement: 손상 항목 빼고 열기
"손상 항목 빼고 열기"를 고르면 시스템은 무엇이 사라지는지 확인을 받은 뒤 손상 키를 격리하고, 그 키를 빈 값으로 바꾼 상태로 앱을 열어야 한다(SHALL). Meta가 손상된 경우에는 새 Meta를 만든다.

#### Scenario: 한 덱만 손상
- **WHEN** 덱 A의 카드 키만 손상된 상태에서 "손상 항목 빼고 열기"를 확인한다
- **THEN** 앱이 열리고 덱 A는 카드 0장, 다른 덱의 카드는 그대로 보인다

#### Scenario: 확인 취소
- **WHEN** "손상 항목 빼고 열기"의 확인에서 취소를 고른다
- **THEN** 복구 화면에 그대로 머물고 저장 값은 바뀌지 않는다

### Requirement: 저장소 읽기 실패
앱 시작 시 저장소 읽기 호출 자체가 실패하면 시스템은 손상과 구분해 데이터를 불러오지 못했다는 안내와 "다시 시도"를 보여 주어야 한다(SHALL). 이때 복구 동작(백업 복구·격리)을 제공해서는 안 된다(MUST NOT).

#### Scenario: 일시적 읽기 실패
- **WHEN** 첫 읽기 호출이 실패하고 "다시 시도"를 눌렀을 때 읽기가 성공한다
- **THEN** 저장 값을 바꾸지 않은 채 홈 화면이 열린다

### Requirement: 저장 실패 재시도와 안내
저장이 실패하면 시스템은 최대 3회까지 간격을 늘려 가며 다시 저장해야 한다(SHALL). 모두 실패하면 화면 안에 저장하지 못했다는 안내와 "다시 시도" 동작을 보여 주어야 한다(SHALL). 안내는 하단 버튼이나 화면 내용을 가리지 않는다. 메모리의 변경은 유지하며, 이후 저장이 한 번이라도 성공하면 안내를 거둔다.

#### Scenario: 일시적 실패 (D-03)
- **WHEN** 첫 저장이 실패하고 두 번째 시도가 성공한다
- **THEN** 안내 없이 변경이 저장소에 저장된다

#### Scenario: 계속 실패
- **WHEN** 저장이 처음 시도와 재시도 3회 모두 실패한다
- **THEN** 저장 실패 안내와 "다시 시도"가 보이고, 화면의 편집 결과는 그대로 남는다

#### Scenario: 다시 시도 성공
- **WHEN** 저장 실패 안내가 보이는 상태에서 저장소가 회복되고 "다시 시도"를 누른다
- **THEN** 변경이 저장되고 안내가 사라진다
