# Proposal

## Why

Day 2 완료 조건("재실행 후 데이터가 유지되고 연쇄 삭제가 동작한다")은 사용자가 직접 과목·덱·카드를 만들고 지울 수 있어야 확인된다. day2-data-layer로 CRUD 규칙과 저장 경로는 준비됐지만 화면이 없어 사용자는 아무것도 입력할 수 없다. 이번 변경은 그 데이터 계층 위에 첫 화면과 화면 이동을 얹어 Day 2를 끝낸다.

## What Changes

- 화면 이동(라우터): 화면 스택을 브라우저 히스토리와 연동한다. 화면 이동은 히스토리에 쌓고, 뒤로가기(토스 내비게이션 바·Android 시스템 백버튼·브라우저)는 히스토리를 한 단계 되돌린다. 최초 화면에서 뒤로가기는 플랫폼 기본 동작(미니앱 종료)에 맡긴다. 새로고침하면 현재 화면을 유지한다.
- 과목·덱 목록 화면(최초 화면): 과목별 덱과 덱별 카드 수를 보여 준다. 과목·덱 생성, 이름 변경, 덱 이동, 삭제(확인 후)를 제공한다. 같은 과목에 같은 이름의 덱이 있으면 경고만 표시한다.
- 덱 상세 화면: 카드 목록(질문 미리보기, 다음 복습일), 카드 추가, 카드 편집 진입, 빈 상태 안내.
- 카드 작성·편집 화면: 질문·정답 입력과 글자 수 표시, 입력 제한 위반 시 안내, 저장, 새 카드의 "저장 후 계속", 기존 카드 삭제(확인 후).
- 로딩·로드 실패 상태 표시. 로드 실패 시 편집을 막는다(복구는 Day 5).
- 이름 입력·삭제 확인·덱 이동에 쓰는 공용 다이얼로그.
- 스타터 화면(`App.tsx`·`App.css`)을 라우터 화면으로 교체한다.

범위 밖: 홈(오늘 복습)·학습 세션·통계·설정 화면(Day 3·4·5), 삭제 실행 취소(F11, P1), 세션 중 뒤로가기 확인(Day 3), 저장 실패 안내 UI(Day 5), TDS 도입(사용하지 않음).

## Capabilities

### New Capabilities
- `app-navigation`: 화면 스택과 히스토리 연동, 뒤로가기·최초 화면·새로고침 시 동작.
- `content-screens`: 과목·덱 목록, 덱 상세, 카드 작성·편집 화면에서 사용자가 볼 수 있는 정보와 할 수 있는 동작, 입력 안내, 삭제 확인, 빈 상태·로딩·로드 실패 표시.

### Modified Capabilities
(없음) — CRUD 규칙·입력 제한·저장은 `study-content`·`data-storage` 요구사항을 그대로 쓴다.

## Impact

- 코드: `reviewq/src/app/router.ts`(신설), `reviewq/src/screens/`(신설: SubjectList, DeckDetail, CardEditor), `reviewq/src/components/`(다이얼로그 등 추가), `reviewq/src/App.tsx` 교체, `reviewq/src/App.css` 제거.
- 의존성: 추가 없음. 스타일은 CSS Modules(Vite 기본 지원)와 `src/styles/tokens.css` 토큰을 쓴다.
- 외부 API: 브라우저 History API(`pushState`·`popstate`). `graniteEvent.backEvent`는 구독하지 않는다(구독 시 기본 뒤로가기가 차단됨).
- 사용자 영향: 스타터 화면 대신 과목·덱 목록 화면이 최초 화면이 된다.
