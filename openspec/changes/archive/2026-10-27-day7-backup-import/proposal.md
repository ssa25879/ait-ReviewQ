# Proposal

## Why

설정에서 백업을 내보낼 수는 있지만(F10) 다시 넣을 방법이 없다. 그래서 기기를 바꾸거나 토스 앱을 다시 설치하면 내보낸 파일이 있어도 카드를 처음부터 손으로 입력해야 한다. 기획서는 백업 가져오기(F13)를 v1.1로 두었지만, 실기기 확인에서 입력 부담이 확인돼 v1.0 출시 전에 넣는다.

## What Changes

- **백업 가져오기**: 설정의 백업 섹션에 "백업 가져오기"를 둔다. 내보내기 파일을 고르거나(파일 선택), 파일 선택이 안 되면 백업 내용을 붙여넣어 불러온다.
- **검증과 요약**: 불러온 내용은 내보내기와 같은 형식 검증과 참조 일관성 검사(덱의 과목·카드의 덱이 있는지)를 통과해야 한다. 통과하면 과목·덱·카드·학습 기록 수와 내보낸 날짜를 보여 준다. 이 앱보다 새 형식 버전의 백업은 거부한다.
- **전체 교체**: 2단계 확인 뒤 지금의 과목·덱·카드·학습 기록을 백업 내용으로 바꾼다. 바꾸기 전에 지금 데이터를 별도 키에 자동으로 보관한다. Meta(설치 식별자·알림 동의 기록)는 유지한다. 저장 대기 중인 변경이 교체 뒤에 다시 쓰이지 않게 한다.

범위 밖: 병합 가져오기, 가져오기 되돌리기 화면(자동 보관본은 키로만 남긴다), 클립보드 읽기 API(권한 추가 필요), 다른 앱 형식(CSV 등) 가져오기.

## Capabilities

### New Capabilities
- `data-import`: 가져오기 진입, 입력 방식(파일 선택·붙여넣기), 형식·버전·일관성 검증과 요약, 2단계 확인, 전체 교체와 자동 보관, 실패 처리.

### Modified Capabilities
(없음)

## Impact

- 코드: `reviewq/src/infra/storage/importData.ts`(신설: 문서 해석·검사·교체), `reviewq/src/app/store.tsx`·`contentContext.ts`(`replaceAll`), `reviewq/src/screens/Settings/`(가져오기 섹션), `reviewq/src/infra/storage/keys.ts`(보관 키), `reviewq/src/screens/messages.ts`.
- 저장: 새 키 `bq:backup:beforeImport`(교체 직전 데이터, 내보내기 형식). 형식 버전 변경 없음.
- 의존성·권한 추가 없음. HTML 파일 입력이 토스 WebView에서 동작하는지는 실기기에서 확인한다(문서에 근거 없음).
