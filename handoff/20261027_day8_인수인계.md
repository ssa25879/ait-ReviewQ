## 5. 환경 메모

- dev 서버는 **프로젝트의 vite**로 띄운다: `cd reviewq && ./node_modules/.bin/vite --port 5199 --strictPort`. `npx vite`를 다른 폴더에서 실행하면 npm 캐시의 vite가 떠서 모든 페이지가 404가 난다(이번 세션에서 발생, `handoff/e2e/.vite/`는 그때 생긴 캐시라 커밋하지 않음).
  - CDP용 포트: 5199 기본, 5198 광고·알림 플래그(`VITE_ADS_ENABLED=true VITE_NOTIFICATION_ENABLED=true VITE_NOTIFICATION_TEMPLATE_CODE=test`), 5197 데모(`VITE_DEMO_DATA=true`).
  - 서버는 `[::1]`에서만 듣는다. PowerShell 확인은 `http://[::1]:5199/`로.
- CDP 스크립트(`handoff/e2e/*.mjs`, 11종)는 **PowerShell에서** `node <스크립트> "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" "<절대경로 출력 폴더>"`로 실행한다(Bash 샌드박스에서는 Edge CDP 연결 실패).
  - `home.mjs`는 `$env:E2E_SHIFT='{"tz":"Pacific/Honolulu","date":"<오늘-1일>"}'`가 필요하다(KST 기준 날짜가 다른 시간대).
  - 스크립트들은 저장소를 비운 뒤 `bq:guide`를 넣어 첫 화면을 홈으로 둔다. 가이드 자체는 `ux.mjs`가 검사한다.
  - 마지막 결과: ux 46, import 38, settings 51, card-input 36, crud 49, review 24, study 68, home 67, stats 21, recovery 43, ads-notify 39 모두 통과. 단위 테스트 247개 통과.
- 데모 플래그 QR 번들 올리기: `cd reviewq && VITE_DEMO_DATA=true npm run build` → 콘솔 MCP `bundle_upload`(빌드가 출력한 deploymentId) → `curl -X PUT -H "Content-Type: application/zip" --data-binary @reviewq.ait '<uploadUrl>'` → `bundle_upload_complete` → `bundle_list`로 `CREATED` 확인 → `bundle_test_push`(privateLink·consoleTestUrl 전달). **출시용은 플래그 없이 다시 빌드**(로컬 `reviewq.ait`가 데모 빌드로 덮여 있을 수 있음).
- 기기 실측 사실: Android에서 `File.saveBase64`는 기기 저장이 아니라 공유 시트로 열린다. 가져오기 "파일 선택" 창은 열린다. `Share.sendMessage`(공유 시트, 권한 불필요)로 백업 코드를 보내는 방식이 주 경로다.
